# 痛点：事实、影响与根因假设

## 不以猜测替代买家

买家说的预算、规格或履约问题可能就是真实原因，不必预设“表面背后另有秘密”。不要因岗位、文化、国籍或话术推断隐藏情绪、被裁风险或心理操纵点。

## 六层观察框架

| 层 | 可以观察什么 | 证据与处理 |
|---|---|---|
| 行业条件 | 已核实的渠道/成本/规范变化 | 只用相关市场的当前来源；不推广为行业人人如此 |
| 明确诉求 | 买家原话和文件要求 | 保留措辞、范围及日期 |
| 业务影响 | 延期开业、预算缺口、返修工作等 | 买家确认时列事实，否则标假设 |
| 根因 | 规格不可比、责任不清、信息不足等 | 列替代解释，提出可验证问题 |
| 感受 | 买家主动表达的担忧/失望 | 可回应，不作诊断或夸张共情 |
| 未说因素 | 决策权、审批或其他未知因素 | 只作询问方向，不能当事实或对客指控 |

不要求把六层都填满；无证据时保留未知，尤其后两层。

报价前须按[需求门槛](discovery_before_quotation.md)取得买家确认的真实痛点或采购目标。没有旧产品问题的新项目可用清楚的目标及验收标准，不制造投诉或无限深挖；首封仍不报价。网站研究只产生待验证假设，不能自动放行报价。

## 常见异议的分流

| 买家说法 | 可能的不同原因 | 最小核查 |
|---|---|---|
| 太贵 | 预算封顶、规格不同、物流成本、还价 | 比较同口径报价；问预算差额 |
| 要证书 | 法规、项目招标、内部资质门槛 | 问标准/型号/用途/目的地，确认现有文件 |
| 不回消息 | 延期、审批、联系人变化、方案不足 | 复查既有往来，用一个低负担决策问题 |
| 对质量没信心 | 先前失败、样品不一致、证据不足 | 问具体风险，提供真实样品/验收/追溯路径 |
| 不信任工厂身份 | 早期陈述与现实冲突 | 纠正具体事实，说明真实安排与可验证控制 |
| 交期不能接受 | 工期、运输、到场安装、预计时间混用 | 分清各节点及关键路径，不重新保证未定日期 |

## 从诊断到行动

每个痛点对应：买家原话→证据→可能影响→根因候选→验证动作→可兑现响应。响应可为资料、规格对比、样品、检验计划、责任澄清或已授权条件调整。

不要用未经证实的零VOC、零缺陷、固定减震/降噪比例、某年限保障、客户收益或银行保证来“解决痛点”。监管、安全或技术判断需要相应当前证据和专业确认。

问题库见[痛点FAQ](../faq/faq_pain_points.md)。完整分级另依评分框架，不把“表达痛苦多”简单当高价值。
